# 开发与本地构建

## 全应用动效

`design/motion.tsx` 统一按压、开关、布局和导航时长；`MotionProvider` 在应用根部
统一监听系统“减少动态效果”，运行中切换也会生效。按钮使用 `MotionPressable`
直接动画化原触摸区域，保持 flex、hitSlop、长按和回调。背景关闭层显式使用
`feedback="none"`，图片缩放、扫码和正文选择继续使用各自的手势。

透明弹层使用 `MotionModal` 保留退出中的内容并隔离触摸/无障碍；全屏查看器保留
原生 presentation。调用方应保持组件挂载并更新 `visible`，条件卸载会跳过退场。
`MotionCollapse` 只在显式开关时过渡高度，流式文字和嵌套内容变高时直接更新尺寸。
导航保留离场页面至动画结束，迟到回调不能删除后来压入的页面。

`npm run test:motion` 覆盖动画中断、快速反向、导航/手势取消、内容保留、系统偏好
和卸载清理；原生手势和实际帧效果仍需在模拟器或设备上验收。

## 聊天阅读位置与刷新

`useChatScroll` 区分用户主动滚动与键盘/窗口尺寸改变：阅读历史时停止自动跟随，
键盘弹出或新内容到达时保留位置；回到底部或成功发送后恢复跟随。所有动画滚动
读取最新系统动效偏好，切会话、隐藏、后台及卸载取消延迟滚动。首次有内容并请求
落底后才启用历史消息锚定，空会话不会提前锁定顶部。聊天输入区在 Android 和 iOS
都通过 KeyboardAvoidingView 的 padding 避让键盘，兼容 Android edge-to-edge 下
adjustResize 未缩小内容窗口的情况，避免输入栏与回到最新按钮被完整软键盘遮挡。

NavHost 向页面传递准确的导航条目 active 状态，Home 再结合所选 tab 控制聊天
可见性。聊天页投影刷新仅在前台可见时运行，等请求完成后再等待 2 秒（运行、
团队未完成或待审批）或 15 秒（空闲）；同一会话在途刷新复用，多个会话与全局
扫描共享在途列表请求。现有全局通知扫描仍保持 5 秒，复用其结果继续检测隐藏
会话的团队完成与管家汇总；停止 UI 轮询不会关闭事件流或审批通道。

`npm run test:copyScroll` 包含滚动、键盘、动效偏好、隐藏/前后台、延迟回调及
刷新合并和团队完成测试。`test:streamingPerf` 继续验证流式折叠与权威运行状态。

## 一体化聊天输入区

`ChatComposer` 将待发送附件、可增长文本框与底部添加/打断/发送操作放在同一
主题容器内。附件显示缩略图或类型标识、文件名与大小，名称从中间省略；移除和
主要操作保留 44dp 触摸区域。审批与团队条继续停靠在容器上方。
组件只负责展示和回调；草稿持久化、附件暂存、安全发送与请求 ID 仍由聊天页和
PendingSend 管理。外层高度测量继续覆盖整个输入区，为回到最新按钮和键盘让位。
Android 在键盘展开时改变屏幕尺寸或窗口宽度，会先收起键盘以清除 RN 缓存的旧键盘坐标；
草稿和附件保留，重新聚焦即可继续输入。普通键盘弹出造成的窗口高度变化不触发此兜底。

## 工具详情与附件名称

工具卡片展开后，参数（edit/write 为参数与变更）和输出可分别折叠；初始收起参数，
保留输出预览。流式更新不重置用户的分区选择，等待返回和空输出分别提示。
长参数和长输出保留完整查看入口；差异预览仍可打开完整差异，原始参数也可查看。
复制全部继续只在全屏查看器里提供。

草稿、待发送、历史附件与交付文件共用 `FileTypeBadge`，按原始扩展名显示类型；
无扩展名或不适合短徽标的后缀回退为“文件”，不影响实际 MIME 判断和打开方式。
长文件名采用单行中间省略，完整名称保留在文本及无障碍标签中；交付说明单独展示，
不再替代真实文件名。`test:toolDiff` 包含分区交互、完整内容和附件名称展示回归。

## 首次加载与操作层级

任务列表、会话任务板和模型选择器在首次请求尚未结束且没有缓存时显示静态
`LoadingSkeleton`；已有内容刷新时继续展示原内容。失败提供重新加载，重试不会
重新盖上骨架；过期响应和卸载回调不能覆盖当前状态。装饰占位不进入读屏焦点，
加载开始只播报一次，不使用循环闪动。

普通审批使用警示色与 ⚠，高危审批保留红色、明确文字和二次确认；错误提示继续
使用危险色。风险判断仍由原有 `assessApprovalRisk` 提供，不代表自动放行。
`actionStyles` 统一审批、确认弹窗与待发送操作的主／次／文字层级，主要触摸区域
至少 44dp；卡片内部的工具标签、队列和代码复制按钮减少重复描边。
Markdown 代码块保留语言／复制标题栏、分隔线和完整可选正文。

待发送长正文按现有 220dp 阅读阈值折叠，展开只影响展示；附件、状态、安全重试和
移除操作始终在正文折叠区域之外。状态变化保留阅读选择，新 requestId 重置选择；
安全重试继续传递原始记录，unknown 仍不可移除。
`npm run test:secondRoundUI` 覆盖加载、重试、延迟响应、审批等级和长正文交互。

## 聊天凭据显示保护

`credentialDisplay` 独立识别常见固定格式 Token、JWT、Authorization Bearer、
带认证 URL 的密码部分及 PEM 私钥块；合并重叠范围，显示时不保留凭据前缀。
这是启发式的屏幕保护，不能识别所有密码，也不修改发送、持久化或重试原文。

已发送用户正文默认遮挡，可用独立的 44dp 按钮逐处显示／隐藏。消息正文或所属
会话／消息变化、导航条目隐藏、App 进入 inactive／background 后均重新隐藏；
普通文本不添加控件或后台监听。待发送正文始终遮挡，不提供显示入口。

长按菜单先识别并遮挡，再截短预览；有凭据时提供「复制隐藏后文本」与明确标注
的「复制原文（含凭据）」。选择原文时仍复制完整原消息，失败不显示成功反馈。
助手 Markdown、工具参数／输出、附件正文和输入草稿不在本轮自动遮挡范围。
屏幕保护不能替代发送前检查、日志脱敏或访问控制。

`npm run test:credentialDisplay` 覆盖识别、逐处显示、身份／可见性／前后台重置、
读屏标签、原文与隐藏后复制，以及待发送 retry 仍使用原记录。原生交互另在隔离
Android 模拟器验收，不使用真实凭据或模型。

## 图片附件与查看器

聊天图片和交付图片共用全屏查看器：双指缩放、放大后拖动、双击放大/还原；
原始比例下左右滑动切图、下滑关闭，亦可用按钮切图和关闭；长按保存图片。
加载或解码失败后显示失败提示，用户显式点击重试才重新读取图片；FileCard
重试会关闭旧查看器并强制重新下载。交付图片打开前校验 expectedSize/SHA256，
不匹配时最多重新下载一次，仍不匹配则拒绝打开。

普通文件下载失败时，卡片保留原因并显示“点击重试”；内置文档读取失败时可
“重新下载并打开”。显式重试会绕过旧缓存，继续执行交付文件大小/摘要校验；
打开请求在重渲染前也会阻止重复点击。

历史附件缓存按连接的 UploadApi 对象、会话和附件 ID 隔离；所有连接共享有界
LRU，最多 32 项、24 MiB（按 data URI 字符数 × 2 估算），失败记录最多 128 项。
显式重试绕过成功缓存和失败记录，并复用同一图片的在途请求。

`npm run test:image` 覆盖图片渲染、附件缓存、加载/重试和查看器手势；
`node tests/butler-mobile-flow-spec.mjs` 另覆盖真实 FileCard 的失败后显式重试、
交付图片大小/摘要校验、单次新下载及篡改拒绝。`npm run test:docview` 覆盖
文档解析和文件/文档失败后的显式重试、连续点击、重新读取及完整性拒绝。
原生手势仍需在设备上验收。

## 任务列表与刷新

任务页使用 `FlatList` 按窗口渲染，卡片通过 `React.memo` 和 Host 单调递增的
`revision` 复用未变化的数据。创建、继续和取消的结果立即合入列表；迟到的旧版本
不能回滚列表或当前详情。列表成员及默认顺序仍以 Host 的完整列表为准。

页面可见且应用在前台时，每次请求结束后才安排下一次刷新：有排队、准备、执行中
或待审批的任务时为 3 秒，其余为 15 秒。切换筛选不会改变这个判断。回到前台、
下拉刷新和任务操作会立即请求；页面被覆盖或应用进入后台后停止轮询。

“全部、待处理、进行中、已结束”筛选在客户端完成，计数基于完整任务集合。
当前接口仍返回完整列表，尚未引入服务端分页。`npm run test:butlerTasks` 覆盖
5000 条任务的引用复用、状态筛选、轮询时序、旧响应隔离和详情/交付文件流程。

## 任务页动效依赖

任务页使用 Reanimated 4.3.4、Worklets 0.8.3、Gesture Handler 2.33.1 和
Bottom Sheet 5.2.14，与当前 React Native 0.81.4 配套锁定。更新这些原生依赖后
需要重新构建 Android/iOS 应用，仅重启 Metro 不会加载新原生模块；iOS 还需更新 Pods。

入口先加载 Gesture Handler，根视图提供手势容器及 Bottom Sheet provider；Babel 的
Worklets 插件放在插件列表末尾。动效跟随系统“减少动态效果”设置。任务详情完全关闭后
才进入会话，避免面板遮挡审批操作。详情每次关闭完成后重建原生面板实例，避免连续提前
返回复用旧挂载动画状态；重开等待新 ref 提交，旧实例回调不再处理。交付物仍使用原来的
完整性校验与文件查看器。

## Windows 构建工具排查

先使用锁文件安装依赖，并按常规执行 Gradle。若 Maven 下载的 AAPT2 报
`stableIds.txt: failed to open: 数据无效 (13)`，可以用 SDK 自带的 AAPT2
单独运行最小资源链接来确认工具问题，再显式传入本机路径：

```bash
./gradlew.bat :app:assembleDebug -Pandroid.aapt2FromMavenOverride="<Android SDK>/build-tools/36.0.0/aapt2.exe"
```

发布签名测试支持 `DSH_TEST_GRADLE_ARGS`（JSON 字符串数组），用于传入本地 Gradle 的 `--offline`、`-I` 和 JDK/SDK 配置；不会跳过签名断言。CI 默认不设置该变量。

React Native 可能自动选择下载的 JDK 17，即使 `JAVA_HOME` 已设为 JDK 21。
若该 JDK 连最小 Java 文件都无法生成 class，而本机 JDK 21 可以，在
`dsh-mobile/android` 目录使用以下可选命令（先将 `JAVA_HOME` 设为 JDK 21）：

```bash
./gradlew.bat --no-daemon --max-workers=2 -I jdk21.init.gradle -Preact.internal.disableJavaVersionAlignment=true :app:assembleDebug -PreactNativeArchitectures=x86_64 -Pandroid.aapt2FromMavenOverride="<Android SDK>/build-tools/36.0.0/aapt2.exe"
```

这个 init script 只调整本次编译器选择，在 Android DSL 定稿时统一 Java/Kotlin
字节码目标为 17，避免原生依赖稍后设置的 Java 1.8 默认值与 Kotlin 17 冲突。
`x86_64` 适用于模拟器；真机需要相应架构。debug APK 依赖 Metro，不能作为正式发布包。
这些参数不更改默认 CI 或正式签名门禁，也不应将开发者的绝对路径写入 Gradle 配置。

# v0.18.1 修复记录

## 公网审批通道

审批 WebSocket 复用已登录服务的主机、端口和 TLS，路径为 `/ws/mobile`。
首次配对显式发送 `publicUrl`；已有设备凭据重连时也使用同一入口，避免回退到
公网不可达的 3081 端口。服务端候选地址必须与登录入口同源且安全级别一致。

React Native 0.81.4 的默认 URL 没有字段 setter，也无法正确解析 WebSocket
主机。审批模块显式使用 `whatwg-url-without-unicode`，防止把审批连接发到网站
根路径而产生 502。未改变全局 URL，也未降低认证要求。

回归测试加载真实 RN URL 源码，使用生产 Babel 配置编译审批客户端，覆盖首次
配对、已有授权重连、TLS、端口和 IPv6。已通过公网隧道验证配对和重连，修复包
亦已完成 Android 手机人工验证。

## 桌面网络修复

一键修复会停止经身份核对的旧 DSH Web 进程，再绑定当前有效网卡地址启动服务，
确认可访问后恢复原来运行的隧道。桌面等待时间与后台修复流程一致，错误提示保留
在界面上；服务未启动或地址失效时不展示可配对二维码。

  `0.18.1-hotfix.2`（180002）并保留授权。
- Windows：桌面便携包 `0.18.1`。
- 验证：移动端完整测试及类型检查、桌面回归测试、公网配对和重连、APK 签名与版本检查。
