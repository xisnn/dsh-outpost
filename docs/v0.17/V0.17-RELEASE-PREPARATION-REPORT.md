## 3. 正式签名 APK 构建、v0.16.7 升级安装与冒烟测试的阻塞说明与一键执行方案

### 3.1 当前阻塞点（需人工输入私有 Keystore 密码）

1. **正式 Keystore 密码安全隔离**：
   - 本地正式签名文件已就绪：`E:\DSH-Signing\dsh-release.keystore`（别名 `dsh-release`，对应公钥证书 SHA-256 为 `191b16cebd6f39f64f8cbbe3fcbdd90e2d845a9d7b1fbe19ccdcd819293a736a`）；
   - 按仓库安全规范（`build-signed-apk.ps1`），正式 Keystore 的密码**从未写入任何文件、环境变量或命令历史**，且当前会话为非交互式沙箱（`Approval prompts are disabled`），AI 代理无法在无密码输入的情况下解锁 `E:\DSH-Signing\dsh-release.keystore`。
2. **历史正式签名测试包的 `versionCode` 注意事项**：
   - 本地 `_acceptance-apk/DSH-Outpost-TEST-0.0.0-verify.local-20261028-015002.apk`（v0.16.7 RC 正式签名验收包，证书 `191b16ce...`）在构建时使用了测试合成版本号 `versionCode = 916204`；
   - 而正式版 `v0.17.0` 按标准公式推导的正式版本号为 `versionCode = 170000`（高于线上正式水位线 `16200`）；
   - 若直接从 `versionCode=916204` 的合成测试包覆盖安装 `versionCode=170000` 的正式包，Android 系统会报 `INSTALL_FAILED_VERSION_DOWNGRADE`（此风险已在 `DSH-OUTPOST-FINAL-RELEASE-ACCEPTANCE.md` §9.4 记录）。
   - 因此：
     - **正式发布包**应使用 `-VersionName 0.17.0 -VersionCode 170000`（供线上真实 `v0.16.x` `versionCode <= 160700` 用户无缝覆盖升级）；
     - 若需在装有 `versionCode=916204` 测试包的模拟器上验证**同签名覆盖升级保留数据**，可额外构建一个 `-VersionName 0.17.0 -VersionCode 917000` 的验收包，或先用正式签名构建一个 `versionCode=160700` 的 `v0.16.7` 基线包再升级到 `versionCode=170000` 的 `v0.17.0` 正式包。

### 3.2 本地生成正式签名 v0.17.0 APK 的命令

请在你的本地 PowerShell 终端运行仓库根目录下的 `build-signed-apk.ps1`（交互式输入密码，不回显、不进历史）：

```powershell
cd E:\work\dsBot
.\build-signed-apk.ps1 `
  -KeystorePath 'E:\DSH-Signing\dsh-release.keystore' `
  -KeyAlias 'dsh-release' `
  -VersionName '0.17.0' `

```

脚本完成后会自动：
1. 调用 `apksigner` 校验签名方案 `v2=true` 且证书 SHA-256 等于 `191b16cebd6f39f64f8cbbe3fcbdd90e2d845a9d7b1fbe19ccdcd819293a736a`；
2. 将正式签名 APK 复制到 `E:\work\dsBot\_acceptance-apk\DSH-Outpost-TEST-0.17.0-<timestamp>.apk` 并生成配套 `SHA256SUMS-<timestamp>.txt`。
3. 你只需将该正式签名 APK 生成在 `_acceptance-apk/` 下（无需在对话中提供任何密码），告知我一声，我即可立即在模拟器上完成正式签名包的升级安装与全部冒烟验证。
