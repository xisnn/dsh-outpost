# 真机验证清单（v0.16.3）

> 为什么需要这份清单：v0.5.4 → v0.16.3 这些版本改的都是「用户能直接感知」的东西
> （图片显示、边缘手势、系统通知、文档查看、会话搜索、安全校验、管家分工规则），
> 但大部分是**在模拟器上验证的**。
>
> 模拟器跟真机有几处关键差异：
> · 手势导航的实现（会和系统返回手势抢左边缘）
> · 通知权限与厂商 ROM 的后台拦截
> · GPU 渲染路径（图片/大文档）
> · 内存限制（2.4MB 图片、大 xlsx 解析）
> · 网络环境（真实防火墙、DNS、证书）
>
> 这些都恰好在新功能的影响范围内。

## 准备

**装哪个包**：GitHub Actions 里「Android APK」这个 workflow 的产物（artifacts）。
找 tag 为 `v0.16.3` 的那次运行，下载 `app-debug.apk` 或 release 包。

**覆盖安装注意**：如果之前装过旧版本，直接覆盖可能报
`INSTALL_FAILED_VERSION_DOWNGRADE`。遇到就先卸载再装（会话列表不会丢，
数据在电脑上；手机上要重新配对一次）。

> **重要**：卸载重装后，**通知权限会重置**，首次启动会重新弹「允许通知」。
> 如果不小心点了「不允许」，去「设置 → 应用 → DSH Outpost → 通知」手动打开，
> 否则第四部分的检查都会失败。

**前置条件**：

- [ ] 电脑上 DSH 已启动，且绑的是局域网 IP（不是 127.0.0.1）
- [ ] 手机和电脑在同一个 Wi-Fi
- [ ] 记下启动日志里的 `token=`（配对要用）
- [ ] 记下电脑的局域网 IP（后面要测「明文只允许私有地址」的拦截）

## 零、安全校验（v0.11.0 新增，优先测）

这部分测的是**应用层地址校验**：明文 HTTP 只允许连私有地址，公网必须 https。

> 为什么优先：这是唯一一处「会主动拒绝用户操作」的功能。
> 如果规则写错，正常连接会被误拦，比不加校验更糟。

| # | 操作 | 预期 | 结果 |
|---|---|---|---|
| 0.1 | 配对页填局域网地址（`http://192.168.x.x:3095`）+ token，连接 | **正常连上**（私有网段应放行） | ☐ |
| 0.2 | 配对页填 `http://8.8.8.8:3095` + 任意 token，连接 | **被拒绝**，提示「拒绝用明文 HTTP 连接公网地址」 | ☐ |
| 0.3 | 配对页填 `http://example.com:3095`，连接 | **被拒绝**，提示改用 https 或局域网 | ☐ |
| 0.4 | 配对页填 `https://` 开头的公网地址 | **允许尝试**（不会再被「明文」规则拦） | ☐ |
| 0.5 | 配对页填 `ftp://192.168.1.1` | 拒绝（不支持的协议） | ☐ |
| 0.6 | 用 Cloudflare 隧道地址（`https://xxx.trycloudflare.com`）配对 | 正常连上 | ☐ |

> 0.2 / 0.3 是关键：如果这两个没被拦住，说明校验没生效。
> 0.1 更重要：如果局域网也被拦了，那就是误伤，必须修。

## 六、管家模式（v0.12.0 重点改了分工规则）

> 这一版修掉了一个**硬矛盾**：原 prompt 一边说「轻活自己干：读文件、看目录」，
> 一边说「你自己不读文件、不执行命令」，模型只能随机选一条，行为飘忽。
>
> 现在规则统一成：**按「多步操作 + 独立上下文」判断**，两种模式差别只在
> 「要不要先问方案」，不在「谁来做」。

### 基本流程

| # | 操作 | 预期 | 结果 |
|---|---|---|---|
| 6.1 | 「我的 → 开启管家模式」 | 首页变成管家对话 | ☐ |
| 6.2 | 首次开启 | 弹出选择工作区的面板 | ☐ |
| 6.3 | 随便聊一句 | 管家正常回复 | ☐ |
| 6.4 | 顶部「闲聊 / 计划」切换 | 滑块正常切换 | ☐ |

### 分工规则（重点验证）

| # | 操作 | 预期 | 结果 |
|---|---|---|---|
| 6.5 | **闲聊模式**说：「读一下 package.json 里 react-native 的版本」 | 管家**自己读并直接回答**，**不派队员** | ☐ |
| 6.6 | 看 6.5 有没有出现队员头像 | **不该出现新队员**（轻活派人是浪费） | ☐ |
| 6.7 | **闲聊模式**说：「帮我写一个完整的登录页面」 | **派队员**，回一句「已安排…」 | ☐ |
| 6.8 | **闲聊模式**说：「数一下当前目录有几个 .ts 文件」 | 自己算完直接答，不该开队员 | ☐ |
| 6.9 | 切到**计划模式**，说同样的话（写登录页） | **先给方案**，末尾问「就这样做吗？」 | ☐ |
| 6.10 | 看到方案后回「可以」 | 开始执行（派队员） | ☐ |
| 6.11 | 计划模式下说「读一下 package.json」 | 也应该**先给方案**（虽然活很轻） | ☐ |
| 6.12 | 6.11 回「可以」后 | **管家自己读**，不该派队员 | ☐ |

> **6.5 / 6.7 是这版的核心**。如果 6.5 派了队员，说明「轻活自己干」没生效；
> 如果 6.7 自己写了，说明「重活派队员」没生效。
>
> **6.12 是关键边界**：计划模式确认后，轻活仍然应该自己做，
> 不能因为「确认过方案」就一律派人。

## 已知的、不用报的问题

- **App 被系统杀掉后收不到通知** —— 这是本地通知的固有边界。要真正做到
  杀进程也能收，得接厂商推送通道（小米/华为/OPPO 各自的 SDK），工作量很大。
- **图片首次加载有几秒等待** —— 图片是完整下载到本地再显示，2 MB 的图在
  局域网上大概 1-2 秒。还没有做渐进式加载。
