# Android 发布与签名验证

正式发布由 `.github/workflows/android.yml` 的标签构建执行。发布前必须通过移动端测试、集成测试、版本号检查、APK 签名有效性检查，以及包名和版本检查。

正式包使用私有签名证书。证书 SHA-256 必须与仓库变量 `EXPECTED_CERT_SHA256` 一致；缺少签名材料、指纹不匹配或使用仓库内的公开 debug 证书时，发布必须失败。下载后的文件完整性通过 Release 附件 `SHA256SUMS.txt` 校验。

## 测试构建与真机升级

`signing-verify.yml` 是独立的签名验证工作流。它的测试包不属于正式发布包；公开仓库不上传这个工作流生成的真实签名测试 APK。需要真机测试时，在本地使用相同验证步骤构建。

测试构建可能使用很高的合成 `versionCode`。Android 会阻止较低 `versionCode` 的 APK 覆盖安装，因此安装测试包后，可能无法直接升级到后续正式版。真机测试应使用独立测试设备或测试环境，完成后卸载测试包；卸载会清除该应用的数据和授权，需要重新配对。不要在保留生产数据的设备上随意安装高版本号测试包。

正式版之间的覆盖升级必须同时满足：包名相同、签名证书相同、`versionCode` 递增。发布前应验证已有授权能在覆盖安装后继续使用，并测试首次配对、断线重连和审批收发。自动化测试通过不等于真机验收完成；具体版本的验收结果以该版本发布说明为准。

## 区分两种签名错误

- 系统安装器拒绝不同证书的覆盖安装，可能报告 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。这是 Android 安装阶段的校验。
- 应用内更新器的 `SignatureMismatchError` 是应用下载更新时发现证书身份不匹配。它会在请求系统安装前阻止更新。

两者的触发阶段不同，不能混为一谈。发布验证需要分别覆盖应用内更新检查和系统安装器的升级行为，不能用其中一项成功代替另一项。
