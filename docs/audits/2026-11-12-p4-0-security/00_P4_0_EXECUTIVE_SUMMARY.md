## 2. 章程八问逐答

### Q1 · D-3 是否真正修复？
**是。** 根因是 `lib/index.mjs:2255` 默认路径只认 `os.homedir()`，忽略 `DSH_HOME`。
修复改为「显式 deviceFile > 非空 DSH_HOME > 默认 ~/.dsh」，派生文件级联跟随。
证据强度：真实上游 0.10.3 源码（四模块逐字节 MATCH）→ 14 个隔离用例 RED(7F/7P)→GREEN(14P)
→ 打过补丁的真实安装包 14/14 → 真实隔离 DSH 首启 `devices=0`（不继承正式注册表）
→ 同 DSH_HOME 第二实例**加载失败并给出明确锁错误**（fail-closed）。
详见 `01`、`02`；日志 `A3-RED-*`、`A3-GREEN-*`、`D3-real-dsh-verification.txt`。

### Q2 · 多实例 / 撤销问题是否解决？
**是（在「独立进程不得共享同一注册表」语义下）。** 采用策略 1「单活所有者」：
`wx` 原子创建锁 + 同 pid 可重入 + 陈旧 pid 回收 + 损坏/不可读/活外部持有者一律 fail-closed。
撤销不再被跨进程快照覆盖复活（共享被直接拒绝）。**合法用法不被阻断**：
同进程多网关（不同文件）、同进程顺序复用均通过（`02` 正向用例）。
策略 2/3 的比较与取舍见 `01` §4。剩余边界见 `09` §1（R5：不防同进程逻辑误用）。

### Q3 · 老用户兼容性？
**完全兼容。** 无 `DSH_HOME` 时解析结果与旧默认**逐字节一致**（CI Node20 与本地 Node24 双验证）；
空白/纯空白 `DSH_HOME` 视为未设置，不产生异常路径；显式 `deviceFile` **原样返回**（不 resolve/不展开 ~）；
`gatewayStateFile`/`cloudflareStateFile` 跟随同一根。**不自动迁移、复制或删除已有设备凭据**；
隔离首启不继承正式注册表。补丁与既有 mgmt-auth 补丁可组合，回滚后 mgmt-auth 逐字节存活（G7）。

### Q4 · 哪些 P1 功能通过真机验收？
**本轮没有使用物理真机**（vivo V1981A 已连接但刻意不用：个人手机上驱动设备控制不可安全恢复）。
通过**真实 Emulator（API 35）**验收的有：原生模块加载与 11 工具注册、phone_screen 快照、
敏感屏 fail-closed 接管、错误目标拒绝（无手势）、Accessibility 授权/撤销/重连、
审批 digest 与用户所见逐字绑定、未授权不执行/拒绝不续调、审批≠放行、
FGS 启动(dataSync)/停止/息屏即停、取消传播与持久化、前后台状态保留、
本地任务创建/运行/取消、异常失败关闭、数据保存/恢复、Keystore 凭据隔离、JNI runner 存在。
矩阵 #1,2,3,10(拒绝),11,12,13,14,20,21,24,26,27,31,32,33,34,35,38。详见 `03`–`06`。

### Q5 · 哪些 P1 风险仍在？
9 项设计缺口（FAIL，静态确认，未擅自修改）：
屏幕世代不校验(#5)、type 同包盲写(#6)、phone_open 先拉起后判敏感(#9)、
原生审批无 TTL(#17)、无息屏恢复(#22)、AgentService 无时限(#23)、协作式取消(#25)、
敏感词子串误报(#15)、test:p3/p4/localRuntime 不在链(#44)。
另加本轮新增 N1（cookie 容器 hang/误导 401）、N2（死胡同工作区弹层）。
BLOCKED：Shizuku 虚拟屏(#29)、本地 runtime 全链路(#37，缺 libproot.so) 及依赖项(#30/#39)。
NOT_RUN：非敏感前台真实手势(#4/#7/#8)、悬浮审批卡(#18)、androidTest 7 项(#43)、全部真机项。
详见 `09` §2–§4、§7。

### Q6 · 是否有安全阻塞项？
**有，两项建议作为 P4 前置门槛**（`09` §6）：
(a) N1 落在凭据/认证路径；(b) #5/#6/#9 是「可对错误目标产生真实副作用」的设备控制缺口。
两者都只交方案待第二方复核。**没有**发现「认证被绕过/审批被自动放行/凭据泄露」类已实现漏洞：
管理接口无 cookie 401、公网门关闭、敏感屏 fail-closed、拒绝不续调均实测成立。
D-3 本身已消除「隔离实例读写正式注册表」这一最高危项。

### Q7 · 是否具备进入 P4（性能/架构）的条件？
**有条件具备。** 回归与 CI 双绿、安全骨架成立、正式数据零触碰、回滚可验证。
但建议先过 `09` §6 的两个前置门槛（修 N1+#5/#6/#9；解锁 #37），
否则性能/架构改动会建立在仍会误动作、且无法端到端验证的地基上。**不建议大规模重构。**

**不可以，本轮也不合并。** main 仍 `e835782`（与 origin/main 相同），HEAD 领先 50 提交但 main 未推进；
无新 Tag（63/63）、无 Release、CI release job skipped。
合并决策属第二方复核与用户授权范围；且 Q6 的前置门槛未清前不应进 main。
