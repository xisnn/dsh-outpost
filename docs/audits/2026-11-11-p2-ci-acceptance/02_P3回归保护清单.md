**守什么**：同一个工具调用可能同时出现在 `assistant/message` 的 tool-call 块和独立的 `tool/call` 事件里。真实 DSH 用 `tool-call.id` 与 `tool/call.callId` 两种拼写指同一个调用，必须合并成**一个**块，不能产生重复卡片。

**保护位置**：`fold/index.ts:407-409`（assistant/message 侧）、`:441-443`（tool/call 侧），均为 `callId ? step.blocks.find(...) : undefined`。

## 五、本轮发现、P3 应顺手处理的测试质量问题

### 5.1 `gateway-startup-gate-spec.mjs:239-244` 恒真断言

```js
if (code !== 0) {
  check(true, '补丁未应用时 apply.mjs --check 返回非 0');   // ← 永不失败
  check(/认证|补丁|apply\.mjs/.test(out) || out.length > 0, 'apply.mjs 给出可读输出');  // ← 几乎恒真
} else {
  check(true, '补丁已应用时 apply.mjs --check 返回 0');     // ← 永不失败
}
```

**实测后果**：该 spec 本地 54 条、CI 55 条——分支取决于运行环境的真实补丁状态，**同一次运行只覆盖一个分支**，且两边各有一条空断言。

**建议**：改为真实断言 `code !== 0` / `code === 0`，并用 fixture 让两个分支在同一次运行中都被覆盖。与 P2 的 `f38d9e2`（契约测试零断言假绿）同类。

`timeout-throttle-spec.mjs` / `throttle-behavior-spec.mjs` 在本地与 CI 全量日志中出现次数均为 **0**。BUG-02 的步骤 3/4 必须把它们接入 CI，否则新守卫永远不运行。
