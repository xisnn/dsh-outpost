# BUG-03 回归保护清单

本清单列出**本轮不得破坏的既有性质**，以及各自守它的测试。所有 spec 都在 `npm run test:chain` 内，本地与远程 CI 都会执行。

## 一、第二方点名的五项保护

| 保护项 | 守它的 spec | 关键断言 |
|---|---|---|
| **工具调用去重** | `fold-spec`、`tool-result-binding-spec` | `assistant/message` 的 `tool-call.id` 与 `tool/call.callId` 合并为 1 个块（B18）；重复事件不产生重复块 |
| **requestId 幂等** | `send-idempotency-spec`、`pending-send-send-flow-spec` | 显式 retry 复用同一 `requestId`；同文本两次新发送产生两个不同 ID |
| **unknown 安全重试** | `revocation-unknown-spec`、`pending-send-state-spec`、`pending-send-send-flow-spec` | 超时/未知落 unknown，不自动重发；重启后仍 unknown |
| **断线重连恢复** | `ws-reconnect-session-recovery-spec`、`tool-result-late-recovery-spec` | 补历史后未绑定结果恢复（L5）；跨轮迟到结果也能恢复（L14） |
| **工具调用折叠** | `workgroup-spec`、`motion-collapse-spec`、`tool-card-sections-spec` | 分组边界/不跨轮/不丢块；Collapse 受控；最终回答在组外 |

## 三、易踩的反向陷阱（本轮实际遇到）

1. **`clearTimeout` 式的「数出现次数」断言**：本轮 `motion-collapse-spec` 的 vm 沙箱有 import 白名单，新增 `../core/toolStatus` 会让它报 `Unexpected import`。正确处理是**把真实模块注入白名单**，不是删断言、也不是塞桩件。
2. **全局 seq 计数器造成的假失败/假通过**：构造「重复事件」时若两次调用工厂函数，seq 会递增，事件其实不同。B19、L3、L17 都踩过；L16 更隐蔽 —— 它因 `endedAt` 不同而**假通过**，掩盖了真正要测的诊断字段比较。修法：比较类用例一律用**显式 seq**。
3. **跨 step 查找不是缺陷**：`tool/result.step` 不是定位调用的权威字段，`callId` 才是。按 step 收窄查找会让合法结果绑不上。
4. **`pending` 语义不能改**：把未确认块的 `pending` 改成 false 会让 fold 的完成卡门禁（`completionStep`）放行，等于把缺失结果当成功。本轮保留 `pending=true` 并新增 `resultUnconfirmed`，门禁自然继续生效。
